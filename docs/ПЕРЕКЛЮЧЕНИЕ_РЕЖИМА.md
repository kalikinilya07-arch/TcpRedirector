# Переключение режима захвата

TcpRedirector поддерживает два механизма перехвата трафика (**WinDivert** и **Wintun**), а режим Wintun — два движка (**embedded** и **external**). Переключение выполняется правкой `config.json` и перезапуском службы — перекомпиляция не требуется.

---

## 1. Какие поля менять

Режим определяется двумя полями в [`config.json`](КОНФИГУРАЦИЯ.md):

| Цель | Поле | Значение |
|------|------|----------|
| WinDivert | `capture_mode` | `"windivert"` |
| Wintun (встроенный) | `capture_mode` + `wintun.engine` | `"wintun"` + `"embedded"` |
| Wintun (внешний) | `capture_mode` + `wintun.engine` | `"wintun"` + `"external"` |

Пример фрагмента для Wintun-external:

```json
{
  "capture_mode": "wintun",
  "wintun": {
    "engine": "external"
  }
}
```

Значения регистр-независимы. Неизвестное `capture_mode` приводится к `"windivert"`, неизвестный `engine` — к `"embedded"` (с предупреждением в лог).

---

## 2. Что положить в `.bin\` (и рядом с EXE)

Перед переключением убедитесь, что зависимости **целевого** режима присутствуют:

| Режим | Обязательные файлы |
|-------|--------------------|
| WinDivert | `WinDivert.dll` и `WinDivert64.sys` рядом с `TcpRedirectorService.exe` |
| Wintun (embedded) | `.bin\wintun\x64\wintun.dll` |
| Wintun (external) | `.bin\wintun\x64\wintun.dll` **и** `.bin\tun2socks\tun2socks.exe` (или путь из `wintun.external_engine.executable`) |

> Файлы **неактивного** режима присутствовать не обязаны. Например, чисто-Wintun развёртывание может вовсе не содержать `WinDivert*` — и наоборот. См. §6.

Где взять внешние бинарники — в [`docs/СБОРКА.md`](СБОРКА.md#5-каталог-bin-и-источники-внешних-бинарников).

---

## 3. Перезапуск службы

Изменения `config.json` применяются при следующем старте службы. Перезапустите её:

```cmd
sc stop TcpRedirectorService
sc start TcpRedirectorService
```

Либо используйте кнопки запуска/остановки в GUI, либо оснастку `services.msc`.

---

## 4. Как проверить активный режим по логам

Служба логирует выбранный режим при инициализации (в `<exeDir>\logs\`). Ищите строки вида:

- `Capture mode: WinDivert`
- `Capture mode: Wintun (embedded engine)`
- `Capture mode: Wintun (external engine)`

А также результаты preflight с префиксом `[windivert]` или `[wintun]` и итоговое `Capture started` при успешном старте. Соответствующая логика — в [`ServiceMain.h`](../src/service/TcpRedirectorService/adapters/driving/ServiceMain.h:214).

---

## 5. Что проверяет preflight в каждом режиме

Перед созданием захвата служба выполняет preflight **только активного** режима (см. [`ServiceMain.h`](../src/service/TcpRedirectorService/adapters/driving/ServiceMain.h:168)). Ошибки делятся на блокирующие (`failures` — служба не стартует) и предупреждения (`warnings` — старт продолжается).

### 5.1. WinDivert — [`WinDivertPreflight.h`](../src/service/TcpRedirectorService/infrastructure/preflight/WinDivertPreflight.h:39)

Блокирующие проверки:

- наличие `WinDivert.dll` рядом с EXE;
- наличие `WinDivert64.sys` (в x86-сборке — `WinDivert32.sys`) рядом с EXE;
- процесс запущен с повышенными правами (администратор / SYSTEM).

Предупреждения (не блокируют): невозможность прочитать версию `WinDivert.dll`; сама версия DLL выводится информационно.

### 5.2. Wintun — [`WintunPreflight.h`](../src/service/TcpRedirectorService/infrastructure/preflight/WintunPreflight.h:44)

Блокирующие проверки (при любом `engine`):

- существует каталог `.bin\`;
- существует `.bin\wintun\x64\wintun.dll` (арх. по разрядности процесса);
- `wintun.dll` реально **загружается** и имеет нужные экспорты (ловит битые/чужие DLL);
- процесс с повышенными правами;
- `wintun.adapter_name` не пустой;
- `wintun.tunnel_ipv4_cidr` корректен (`a.b.c.d/N`, `N` ∈ [0..32]).

Дополнительно при `engine="external"`:

- `wintun.external_engine.executable` не пустой и файл существует (относительный путь резолвится от каталога EXE);
- `wintun.external_engine.socks5_listen` разбирается как `host:port`, порт ∈ [1..65535].

Предупреждения (не блокируют): загруженная версия драйвера Wintun; обнаружение уже существующего адаптера с тем же именем (будет переиспользован при `Open()`); резолвленный абсолютный путь к `tun2socks.exe`.

---

## 6. Отсутствие бинарников неактивного режима не мешает старту

Это принципиальное свойство архитектуры: preflight инстанцируется **только для активного режима**. Поэтому:

- в режиме `windivert` отсутствие `wintun.dll`/`tun2socks.exe` **не** приводит к ошибке;
- в режиме `wintun` отсутствие `WinDivert.dll`/`WinDivert64.sys` **не** приводит к ошибке.

Это позволяет распространять «урезанные» поставки (только WinDivert или только Wintun) — см. компоненты инсталлятора в [`docs/СБОРКА.md`](СБОРКА.md#4-сборка-инсталлятора).

## 7. Типичные ошибки preflight и их причины

| Сообщение (фрагмент) | Режим | Причина / решение |
|----------------------|-------|-------------------|
| `WinDivert.dll not found next to service EXE` | windivert | Положите `WinDivert.dll` рядом с `TcpRedirectorService.exe` |
| `WinDivert driver file not found ... WinDivert64.sys` | windivert | Положите `WinDivert64.sys` рядом с EXE |
| `Service process is not elevated` | оба | Запускайте под администратором/SYSTEM; служба под `LocalSystem` это условие выполняет автоматически |
| `Bin directory does not exist` | wintun | Создайте каталог `.bin\` рядом с EXE и наполните его |
| `wintun.dll not found (expected: ...\.bin\wintun\x64\wintun.dll)` | wintun | Скачайте Wintun с [wintun.net](https://www.wintun.net) и поместите x64-версию по указанному пути |
| `wintun.dll failed to load` | wintun | DLL повреждена/несовместима по разрядности — замените корректной x64-версией |
| `wintun.adapter_name is empty` | wintun | Задайте непустое `wintun.adapter_name` |
| `wintun.tunnel_ipv4_cidr is invalid` | wintun | Исправьте на формат `a.b.c.d/N`, например `10.6.7.1/24` |
| `wintun.external_engine.executable not found` | wintun/external | Поместите `tun2socks.exe` по пути из `executable` (по умолчанию `.bin\tun2socks\tun2socks.exe`) |
| `wintun.external_engine.socks5_listen is not host:port ...` | wintun/external | Задайте корректный `host:port`, например `127.0.0.1:1080` |

При наличии блокирующих ошибок служба логирует `Refusing to start: N failure(s) for mode '...'` и остаётся в состоянии Stopped. После исправления `config.json` и/или добавления файлов перезапустите службу (§3).

## 8. Замечания по переходу между режимами

- **WinDivert → Wintun.** Убедитесь, что `wintun.dll` (и `tun2socks.exe` для external) на месте; смените `capture_mode` на `"wintun"`; перезапустите службу. В Wintun-режиме через туннель уходит **весь** IPv4-TCP (split-tunnel маршруты `0.0.0.0/1` + `128.0.0.0/1`), но embedded-движок при `wintun.process_filter_enabled=true` (по умолчанию) **фильтрует его по процессу** так же, как WinDivert: проксируется только трафик приложений из `apps[]`. **Поведение не-целевого трафика (DIRECT) в embedded** зависит от `wintun.direct_passthrough` (Задача 3): по умолчанию (`false`) DIRECT **отклоняется**, а при `true` идёт **напрямую** мимо прокси через физический интерфейс (см. [`docs/КОНФИГУРАЦИЯ.md`](КОНФИГУРАЦИЯ.md) §10.4). Итог — чтобы не-целевой трафик шёл напрямую, включите `wintun.direct_passthrough=true` (или используйте `capture_mode=windivert`); чтобы проксировать **весь** трафик — `wintun.process_filter_enabled=false`. Подробнее — [`docs/КОНФИГУРАЦИЯ.md`](КОНФИГУРАЦИЯ.md) §10.2 и §10.4.
- **embedded → external.** Помимо смены `engine` на `"external"` проверьте `external_engine.executable` и `socks5_listen`. В external-режиме служба поднимает SOCKS5-слушатель relay и запускает `tun2socks.exe` как дочерний процесс (с авто-рестартом). **Важно:** external-движок **не** поддерживает фильтрацию по конкретному процессу (`process_filter_enabled` игнорируется) — весь трафик туннеля проксируется. Аналогично **не** поддерживается **per-user Kerberos-аутентификация** (`auth.per_user_enabled`): в external-режиме соединение нельзя сопоставить с исходным PID/пользователем, поэтому per-user auth недоступна — соединения обрабатываются по `auth.fallback_policy` (по умолчанию `drop` — закрываются). Если нужна фильтрация по процессу **или** per-user auth, оставайтесь на `engine="embedded"` или `capture_mode="windivert"`. См. [`docs/ИЗВЕСТНЫЕ_ПРОБЛЕМЫ.md`](ИЗВЕСТНЫЕ_ПРОБЛЕМЫ.md) (L2) и [`docs/КОНФИГУРАЦИЯ.md`](КОНФИГУРАЦИЯ.md) §7.
- **Wintun → WinDivert.** Смените `capture_mode` на `"windivert"`, убедитесь в наличии `WinDivert*` файлов, перезапустите службу. Драйвер WinDivert загружается лениво при первом `WinDivertOpen()`.

Подробное описание потоков данных в каждом режиме — в [`docs/АРХИТЕКТУРА.md`](АРХИТЕКТУРА.md#3-потоки-данных-по-режимам).
