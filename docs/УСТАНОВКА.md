# Установка и запуск как службы Windows

Документ описывает установку TcpRedirector на сторонний ПК и запуск в качестве службы Windows для постоянной фоновой работы под учётной записью `LocalSystem` (без интерактивного входа пользователя).

---

## 1. Требования

- **ОС:** Windows 10 / Windows 11, **x64**.
- **Права:** установка и работа требуют прав **администратора**. Служба регистрируется с автозапуском и работает под `LocalSystem`.
- **Visual C++ runtime:** `TcpRedirectorService.exe` и `TcpRedirectorAuthHelper.exe` собраны с динамическим CRT (`/MD`), поэтому им нужны `vcruntime140.dll`, `vcruntime140_1.dll` и `msvcp140.dll`. **Эти DLL уже входят в поставку** (и инсталлятор, и ZIP кладут их рядом со службой), поэтому **отдельно ставить Visual C++ Redistributable не требуется**. GUI поставляется как self-contained .NET (`win-x64`) со своим рантаймом — **устанавливать .NET Desktop Runtime тоже не нужно**.
- **Бинарники активного режима** должны лежать рядом со службой:
  - режим WinDivert — `WinDivert.dll` и `WinDivert64.sys` рядом с `TcpRedirectorService.exe`;
  - режим Wintun — `.bin\wintun\x64\wintun.dll` (и `.bin\tun2socks\tun2socks.exe` при `engine=external`).

Файлы **неактивного** режима не обязательны — preflight их не проверяет (см. §7 и [`docs/ПЕРЕКЛЮЧЕНИЕ_РЕЖИМА.md`](ПЕРЕКЛЮЧЕНИЕ_РЕЖИМА.md)).

- **Для per-user Kerberos-аутентификации** (опциональной функции, `auth.per_user_enabled=true`):
  - `TcpRedirectorAuthHelper.exe` должен лежать **рядом** с `TcpRedirectorService.exe` (служба резолвит путь helper'а относительно своего EXE через `AppPaths`). Инсталлятор ставит его как компонент `core` вместе со службой; при ZIP-поставке он уже включён;
  - хост должен быть **в домене AD**, а пользователи — иметь интерактивный/консольный/RDP-вход (нужен реальный Kerberos-билет);
  - если `TcpRedirectorAuthHelper.exe` отсутствует, функция **недоступна** — соединения обрабатываются по `auth.fallback_policy` (по умолчанию `drop` — закрываются). Сама служба при этом стартует нормально. Подробнее — в [`docs/КОНФИГУРАЦИЯ.md`](КОНФИГУРАЦИЯ.md) §7 и [`docs/ИЗВЕСТНЫЕ_ПРОБЛЕМЫ.md`](ИЗВЕСТНЫЕ_ПРОБЛЕМЫ.md).

## 2. Установка через инсталлятор (рекомендуется)

1. Запустите **`TcpRedirector_Setup.exe`** от имени администратора.
2. Выберите профиль компонентов (шаг «Компоненты»):
   - **Полная (оба режима)** — ставит оба движка (если бинарники доступны);
   - **Только WinDivert** — только WinDivert;
   - **Только Wintun** — `wintun.dll` (+ `tun2socks.exe`, если есть);
   - **Выборочная** — вручную.
3. Завершите мастер. Инсталлятор автоматически:
   - копирует службу в `C:\Program Files\TcpRedirector\`, а GUI — в `...\gui\`;
   - создаёт `config.json` из `config.default.json` **только если** его ещё нет (правки при обновлении сохраняются);
   - выполняет `TcpRedirectorService.exe --install` и `sc start TcpRedirectorService`.
4. При желании установите ярлык на рабочий стол (шаг «Дополнительные значки»).

> ZIP-поставка: распакуйте архив и запустите `install.bat` **от имени администратора** — он выполняет те же действия (создаёт каталоги, копирует файлы, ставит и запускает службу, создаёт ярлыки).

---

## 3. Ручная установка

Если инсталлятор не используется:

1. Скопируйте каталог поставки в целевое расположение, например `C:\Program Files\TcpRedirector\`. Структура должна быть такой:

   ```
   C:\Program Files\TcpRedirector\
   ├─ TcpRedirectorService.exe
   ├─ TcpRedirectorAuthHelper.exe        (для per-user Kerberos-аутентификации)
   ├─ vcruntime140.dll                  (MSVC CRT — обязателен рядом со службой)
   ├─ vcruntime140_1.dll                (MSVC CRT)
   ├─ msvcp140.dll                      (MSVC CRT)
   ├─ config.json                       (или config.default.json → переименуйте)
   ├─ gui\TcpRedirectorGUI.exe
   ├─ WinDivert.dll, WinDivert64.sys     (для режима WinDivert)
   └─ .bin\
      ├─ wintun\x64\wintun.dll           (для режима Wintun)
      └─ tun2socks\tun2socks.exe         (для Wintun engine=external)
   ```

   > `TcpRedirectorAuthHelper.exe` нужен **только** для опциональной per-user Kerberos-аутентификации (`auth.per_user_enabled=true`) и **должен оставаться рядом** со службой — служба запускает его из своего каталога. Для развёртываний без этой функции файл можно не размещать.

2. Положите бинарники нужного режима в правильные пути (см. §1 и структуру выше).
3. Установите службу командой (командная строка **от администратора**):

   ```cmd
   "C:\Program Files\TcpRedirector\TcpRedirectorService.exe" --install
   ```

   Служба регистрируется под именем **`TcpRedirectorService`** с типом запуска **автоматический** (`SERVICE_AUTO_START`) и работает как `SERVICE_WIN32_OWN_PROCESS` под `LocalSystem`.
4. Запустите службу:

   ```cmd
   sc start TcpRedirectorService
   ```

> **Флаги командной строки** (реализованы в [`main.cpp`](../src/service/TcpRedirectorService/main.cpp:74)): `--install` — установить службу; `--uninstall` — остановить и удалить; `--console` — запустить в консольном (не-службовом) режиме для отладки. Других флагов нет.

## 4. Проверка состояния службы

```cmd
sc query TcpRedirectorService
```

В выводе поле `STATE` должно быть `4 RUNNING`. Если служба сразу останавливается — вероятно, provalen preflight активного режима: проверьте логи (§6). Также можно посмотреть службу в оснастке `services.msc` (отображаемое имя — **TcpRedirector Service**).

---

## 5. Автозапуск

Служба устанавливается с автоматическим типом запуска (`SERVICE_AUTO_START`), поэтому стартует при загрузке Windows без входа пользователя — это и обеспечивает постоянную фоновую работу. Проверить/изменить тип запуска:

```cmd
sc qc TcpRedirectorService
sc config TcpRedirectorService start= auto
```

---

## 6. Просмотр логов

Логи пишутся в каталог **`<каталог службы>\logs\`** (например `C:\Program Files\TcpRedirector\logs\`). Путь резолвится относительно EXE, что корректно работает и под SCM (где рабочий каталог = `System32`).

- Уровень логирования задаётся полем `log.level` в `config.json` (0=ERROR, 1=WARN, 2=INFO, 3=DEBUG).
- Ротация — по размеру (`log.maxSizeMB`).
- В логах видно: результат миграции конфига, выбранный режим захвата, результаты preflight, старт relay и capture, ошибки авторизации на прокси.

Для отладки полезно временно поднять уровень до `3` (DEBUG) и перезапустить службу.

---

## 7. Права и учётная запись

- Установка/удаление службы и её работа требуют **прав администратора**.
- Служба работает под **`LocalSystem`** — этого достаточно для WinDivert и Wintun (оба требуют повышенных привилегий). Preflight обоих режимов явно проверяет «elevated»-контекст (`TokenElevation`); под `LocalSystem` это условие всегда выполнено.
- Путь к `config.json`, логам и `.bin\` резолвится от каталога EXE, поэтому запуск под SCM (cwd=`System32`) не ломает пути.

---

## 8. Консольный режим (отладка)

Для диагностики службу можно запустить как обычный консольный процесс — с выводом в реальном времени:

```cmd
"C:\Program Files\TcpRedirector\TcpRedirectorService.exe" --console
```

В этом режиме `Initialize()` и `Run()` выполняются в текущем процессе; остановка — по `Ctrl+C`. Запускать нужно **из консоли с правами администратора**, иначе preflight завершится ошибкой «process is not elevated».

## 9. Удаление

Через инсталлятор — стандартным способом (Панель управления → Программы, либо `uninstall.bat` от администратора). Вручную:

```cmd
"C:\Program Files\TcpRedirector\TcpRedirectorService.exe" --uninstall
```

Команда останавливает и удаляет службу `TcpRedirectorService`.

> **Сохраняемое состояние:** штатное удаление (инсталлятор / `uninstall.bat`) намеренно **не** удаляет `config.json`, каталог `logs\` и содержимое `.bin\` — это позволяет переустановке/обновлению сохранить настройки и добавленные администратором бинарники. Для полной очистки удалите каталог установки вручную. Драйвер `WinDivert` при удалении убирается только если он был реально создан (в чисто-Wintun развёртывании его нет).

> **Per-user auth helper при удалении.** `TcpRedirectorAuthHelper.exe` устанавливается как часть компонента `core` (рядом со службой), поэтому штатное удаление его **убирает** вместе со службой. Запущенные экземпляры helper'а завершаются автоматически при остановке службы (они удерживаются под Job Object с `KILL_ON_JOB_CLOSE`), а также на logoff соответствующего пользователя.

## 10. Поведение антивирусов и EDR

- **Режим Wintun.** `wintun.dll` — это драйвер WireGuard, **подписанный Microsoft** и широко доверяемый. Как правило, не вызывает срабатываний AV/EDR. Это делает Wintun предпочтительным в строгих корпоративных окружениях.
- **Режим WinDivert.** WinDivert использует собственный kernel-драйвер (`WinDivert64.sys`), который антивирусы и EDR иногда помечают как потенциально нежелательный (перехват сетевого трафика — «подозрительное» поведение). В таких окружениях может потребоваться добавить **исключения** для `TcpRedirectorService.exe`, `WinDivert.dll` и `WinDivert64.sys`.

  > Исторически в проекте существовал отдельный документ с рекомендациями по исключениям для Kaspersky (`KASPERSKY_EXCLUSIONS`). Он больше не поставляется; общий принцип прежний: если WinDivert блокируется — добавьте перечисленные файлы и службу в исключения соответствующего защитного ПО, либо перейдите на режим Wintun.

Аналитическое сравнение WinDivert с альтернативами приведено в [`docs/WINDIVERT_ALTERNATIVES.md`](WINDIVERT_ALTERNATIVES.md).
