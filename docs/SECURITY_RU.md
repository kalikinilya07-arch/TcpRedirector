# Меры защиты информации — TcpRedirector v1.1.5

## 1. Область применения

Настоящий документ описывает реализованные в TcpRedirector меры защиты информации при обработке сетевого трафика, аутентификационных данных и конфигурационной информации.

## 2. Модель угроз

### 2.1. Защищаемые активы

| Актив | Классификация | Место хранения |
|-------|---------------|----------------|
| Учётные данные прокси (логин/пароль) | Конфиденциально | `config.json` (DPAPI-шифрование) |
| Kerberos-токены (Negotiate) | Конфиденциально | Только в памяти, время жизни — один CONNECT |
| Конфигурация правил маршрутизации | Служебная | `config.json` |
| Логи соединений | Служебная | `%ProgramData%\TcpRedirector\logs\` |
| Трафик пользовательских приложений | Конфиденциально | Транзит (не сохраняется) |

### 2.2. Субъекты угроз

| Субъект | Уровень доступа | Вектор атаки |
|---------|-----------------|--------------|
| Локальный пользователь без прав администратора | Пользователь | Доступ к named pipe, GUI |
| Локальный администратор | Администратор | Полный доступ к системе |
| Вредоносное ПО в пользовательской сессии | Пользователь | Доступ к named pipe, перехват GUI |
| Сетевой злоумышленник | Сеть | Перехват трафика между сервисом и прокси |

## 3. Реализованные меры защиты

### 3.1. Защита учётных данных

#### 3.1.1. DPAPI-шифрование пароля

Пароль прокси хранится в `config.json` в зашифрованном виде с использованием Windows Data Protection API (DPAPI):

```
config.json → auth.encryptedPassword → DPAPI (user scope, LocalSystem)
```

- **Область действия**: текущий пользователь (для GUI) или LocalSystem (для сервиса)
- **Алгоритм**: AES-256 (предоставляется DPAPI)
- **Энтропия**: дополнительная энтропия из фиксированной строки
- **Пароль в памяти**: хранится в открытом виде только в `ProxyConfig::plain_password`, очищается при уничтожении объекта

**Код**: [`ConfigManager.cpp`](../src/service/TcpRedirectorService/infrastructure/config/ConfigManager.cpp) — методы `EncryptPassword()` / `DecryptPassword()`.

#### 3.1.2. Kerberos-токены

- Токены Negotiate генерируются **в пользовательской сессии** через AuthAgent (не в SYSTEM-контексте)
- Контекст SSPI живёт ровно один HTTP CONNECT
- После успешного CONNECT или ошибки контекст немедленно уничтожается: [`CloseContext()`](../src/service/TcpRedirectorService/infrastructure/auth/KerberosAgentProvider.cpp:110)
- Токены **никогда не сохраняются** на диск и не логируются

### 3.2. Контроль доступа к IPC

#### 3.2.1. Named Pipe: сервис

- Имя: `\\.\pipe\TcpRedirectorService`
- Security Descriptor: `EVERYONE` (GENERIC_READ) — чтение доступно всем, запись невозможна для не-администраторов
- GUI подключается как клиент, сервис только отправляет данные
- **Код**: [`PipeServer.h`](../src/service/TcpRedirectorService/infrastructure/ipc/PipeServer.h:183)

#### 3.2.2. Named Pipe: AuthAgent

- Имя: `\\.\pipe\TcpRedirectorAuth`
- Security Descriptor: `EVERYONE` (полный доступ) — **только одна сессия может подключиться** (no sharing)
- Сервис (SYSTEM) подключается как клиент
- **Код**: [`KerberosAgentProvider.cpp`](../src/service/TcpRedirectorService/infrastructure/auth/KerberosAgentProvider.cpp:160)

#### 3.2.3. Ограничения

- **Критическое**: Named pipe AuthAgent создаётся без security descriptor → любой локальный пользователь может подключиться и отправлять запросы. **Рекомендация**: добавить ACL с ограничением `LocalSystem` и `Administrators`.
- **Смягчение**: pipe создаётся с `no sharing` (только одно подключение), что ограничивает атаку одним злоумышленником за раз.

### 3.3. Защита конфигурации

#### 3.3.1. Атомарная запись

- `config.json` записывается через временный файл + атомарное переименование
- Исключает повреждение конфига при сбое питания или аварийном завершении
- **Код**: [`ConfigManager.cpp`](../src/service/TcpRedirectorService/infrastructure/config/ConfigManager.cpp) — метод `Save()`

#### 3.3.2. Изоляция GUI

- GUI — единственный писатель `config.json`
- Сервис только читает конфиг при старте и по команде reload
- **Код**: [`ServiceMain.h`](../src/service/TcpRedirectorService/adapters/driving/ServiceMain.h:261) — `reloadConfig` callback

### 3.4. Защита сетевого трафика

#### 3.4.1. Изоляция relay-порта

- Relay-сервер слушает `127.0.0.1:34010` — недоступен извне
- Принимает только соединения, перенаправленные WinDivert с локального хоста

#### 3.4.2. Аутентификация на прокси

- Поддерживается Kerberos/Negotiate (SSPI) — безопаснее Basic
- Basic-пароль передаётся только внутри HTTP CONNECT к прокси (localhost/локальная сеть)

### 3.5. Защита логов

#### 3.5.1. Ротация логов

- Максимальный размер файла: 10 МБ (по умолчанию)
- Максимальное количество файлов: 5
- Старые логи сжимаются (gzip) для экономии места
- **Код**: [`LogRotator.cpp`](../src/service/TcpRedirectorService/infrastructure/logging/LogRotator.cpp)

#### 3.5.2. Конфиденциальность логов

- Пароли и Kerberos-токены **не логируются**
- В логах соединений сохраняются: IP-адреса назначения, порты, имена процессов, объём трафика
- **Рекомендация**: включить шифрование диска (BitLocker) для защиты логов на диске

### 3.6. Запуск AuthAgent в пользовательской сессии

- AuthAgent запускается через `CreateProcessAsUserW()` с токеном пользователя
- Токен дублируется с минимально необходимыми правами: `TOKEN_QUERY | TOKEN_DUPLICATE | TOKEN_ASSIGN_PRIMARY`
- **Код**: [`KerberosAgentProvider.cpp`](../src/service/TcpRedirectorService/infrastructure/auth/KerberosAgentProvider.cpp:283)

### 3.7. Целостность кода

- Все исполняемые файлы компилируются из исходного кода (C++ сервис, C# GUI)
- Рекомендуется подписание исполняемых файлов (Authenticode) для защиты от подмены

## 4. Остаточные риски

| Риск | Уровень | Смягчение |
|------|---------|-----------|
| Доступ к named pipe AuthAgent | Средний | Добавить ACL (в плане) |
| Пароль в памяти сервиса | Низкий | Доступен только SYSTEM |
| Перехват трафика сервис→прокси | Низкий | Локальный хост / локальная сеть |
| DoS через множественные подключения | Низкий | Ограничение количества подключений к прокси |

## 5. Рекомендации по усилению защиты

1. **Добавить ACL на named pipe AuthAgent** — ограничить доступ `LocalSystem` и `Administrators`
2. **Подписать исполняемые файлы** — Authenticode сертификат
3. **Включить BitLocker** — для шифрования логов и конфигурации на диске
4. **Настроить брандмауэр** — ограничить доступ к порту 34011 (IPC) только для localhost
5. **Аудит логов** — настроить мониторинг логов на предмет аномалий

## 6. Соответствие стандартам

Продукт учитывает требования следующих стандартов и практик:
- **CWE-256**: пароль не хранится в открытом виде (DPAPI)
- **CWE-522**: учётные данные защищены при передаче (Kerberos/Negotiate)
- **CWE-312**: токены не сохраняются на диск
- **OWASP Top 10**: A07:2021 — Identification and Authentication Failures (учтено)
