# Сборка и упаковка поставки

Документ описывает, как собрать TcpRedirector из исходников и подготовить готовую поставку (инсталлятор или ZIP) для установки на сторонние ПК.

---

## 1. Необходимые инструменты

| Инструмент | Назначение | Примечание |
|------------|------------|------------|
| **Visual Studio 2022** (или Build Tools 2022) | Компиляция службы (MSVC, C++20) | Требуется workload «Desktop development with C++». `build.bat` находит VS через `vswhere.exe` |
| **.NET SDK 9** | Сборка GUI (self-contained, `win-x64`) | Используется `dotnet publish` |
| **Inno Setup** | Сборка инсталлятора `TcpRedirector_Setup.exe` из [`installer/setup.iss`](../installer/setup.iss) | Опционально — можно ограничиться ZIP-пакетом |
| **PowerShell** | Создание ZIP-пакета (`Compress-Archive`) | Входит в состав Windows |
| Внешние бинарники (опц.) | `wintun.dll`, `tun2socks.exe`, WinDivert | См. §5; каждый бинарник опционален |

Компиляция ориентирована на **x64**: `build.bat` инициализирует окружение командой `VsDevCmd.bat -arch=x64`.

---

## 2. Сборка: `build.bat`

Основной скрипт сборки — [`build.bat`](../build.bat) в корне репозитория. Он должен запускаться из корня (проверяет наличие файла `VERSION`). Последовательность шагов:

```bat
build.bat
```

1. **Определение окружения.** Находит Visual Studio через `vswhere`, инициализирует x64-окружение MSVC.
2. **Очистка** каталога `build\`.
3. **[1/3] Юнит-тесты.** Компилирует и запускает [`RuleEngineTest.cpp`](../tests/unit/service/RuleEngineTest.cpp) (`cl /std:c++20`). При провале сборка прекращается.
4. **[2/3] GUI.** Выполняет `dotnet publish TcpRedirectorGUI.csproj -c Release --self-contained true -r win-x64` в `build\gui\`.
5. **[3/3] Служба.** Собирает [`TcpRedirectorService.vcxproj`](../src/service/TcpRedirectorService/TcpRedirectorService.vcxproj) через `msbuild` (Release/x64) и копирует `TcpRedirectorService.exe` в `build\`.
6. **Стадия опциональных бинарников** (`__stage__`): копирует в `build\` те внешние файлы, что найдены, — `WinDivert.dll` + `WinDivert64.sys`, `wintun.dll` (x64), `.bin\tun2socks\tun2socks.exe`, а также `config.default.json` из `installer\`. Каждый файл **опционален**: отсутствие даёт `[SKIP]`, а не ошибку. Так поддерживаются сборки «только WinDivert» и «только Wintun».

### Артефакты сборки

После `build.bat` в каталоге `build\` окажутся:

```
build\
├─ TcpRedirectorService.exe
├─ gui\                      (self-contained GUI: TcpRedirectorGUI.exe + рантайм)
├─ WinDivert.dll             (если найден)
├─ WinDivert64.sys           (если найден)
├─ wintun.dll                (если найден)
├─ .bin\tun2socks\tun2socks.exe   (если найден)
└─ config.default.json       (seed, если найден)
```

## 3. Версионированный релиз: `deploy.bat`

Скрипт [`deploy.bat`](../deploy.bat) упаковывает содержимое `build\` в версионированный релиз `releases\v<VERSION>\`:

```bat
deploy.bat
```

Он:

1. проверяет наличие `build\TcpRedirectorService.exe` (иначе — «Run build.bat first»);
2. создаёт `releases\v<VERSION>\`;
3. копирует службу и GUI (удаляя лишние отладочные файлы и не-русские языковые ресурсы);
4. копирует **опциональные** WinDivert / `wintun.dll` / `tun2socks.exe` (с фолбэком на репозиторный `.bin\`, если в `build\` их нет);
5. кладёт `config.default.json` как seed;
6. авто-инкрементирует patch-версию в файле `VERSION`.

Результат — самодостаточный каталог релиза с исполняемыми файлами и (опционально) бинарниками движков.

## 4. Сборка инсталлятора

### 4.1. Inno Setup — `installer/setup.iss`

Скрипт [`installer/setup.iss`](../installer/setup.iss) собирает `TcpRedirector_Setup.exe`. Особенности:

- **Компоненты выбора режима** (`[Types]` / `[Components]`): «Полная (оба режима)», «Только WinDivert», «Только Wintun», «Выборочная». Компонент `core` (служба + GUI) устанавливается всегда.
- Все внешние бинарники объявлены с флагом `skipifsourcedoesntexist` — отсутствие файла на build-хосте просто исключает его из пакета.
- **Seed-конфиг:** `config.default.json` копируется в `{app}\config.json` только если файла ещё нет (`onlyifdoesntexist`) — правки администратора при обновлении не затираются.
- В `[Run]` инсталлятор ставит и запускает службу: `TcpRedirectorService.exe --install`, затем `sc start TcpRedirectorService`.
- В `[UninstallRun]` служба останавливается и удаляется; драйвер `WinDivert` удаляется только если он реально существует.

Инсталлятор берёт файлы из подкаталога `obfuscated\` (`SourceDir=obfuscated`), который наполняет `package.bat`.

### 4.2. `installer/package.bat`

Скрипт [`installer/package.bat`](../installer/package.bat) стейджит файлы в `obfuscated\` и дополнительно создаёт ZIP-поставку с `install.bat` / `uninstall.bat`.

> **Важно (фактическое поведение):** `package.bat` берёт исходные файлы из каталога **`..\deploy_v3\`** (переменная `DEPLOY=..\deploy_v3`), а `config.default.json` — из `installer\config.default.json`. То есть перед запуском `package.bat` собранные артефакты (служба, `gui\`, опциональные бинарники) должны находиться в каталоге `deploy_v3\` рядом с корнем репозитория. Служба (`TcpRedirectorService.exe`) обязательна — при её отсутствии скрипт завершается с ошибкой; все внешние бинарники опциональны.

`package.bat`:

1. очищает `obfuscated\` и `output\`;
2. копирует GUI (удаляя отладочные и не-русские файлы) и службу;
3. копирует опциональные `WinDivert.dll`+`WinDivert64.sys`, `wintun.dll`, `.bin\tun2socks\tun2socks.exe`;
4. стейджит `config.default.json`;
5. генерирует `install.bat` и `uninstall.bat` (режим-агностичные);
6. создаёт `output\TcpRedirector_<version>.zip`.

После этого можно скомпилировать `setup.iss` в Inno Setup, чтобы получить `output\TcpRedirector_Setup.exe`.

## 5. Каталог `.bin\` и источники внешних бинарников

Внешние бинарники движков хранятся в каталоге `.bin\` (в репозитории) и в рантайме резолвятся относительно каталога службы (`<exeDir>\.bin\`). Фактическая структура репозиторного `.bin\`:

```
.bin\
├─ wintun\
│  ├─ x64\wintun.dll        ← используется в x64-сборке (ОСНОВНОЙ)
│  ├─ x86\wintun.dll
│  ├─ arm\wintun.dll
│  └─ arm64\wintun.dll
└─ tun2socks\
   └─ tun2socks.exe
```

Preflight Wintun-режима ищет DLL по пути **`.bin\wintun\x64\wintun.dll`** (арх. выбирается по разрядности процесса). Внешний движок ищет `tun2socks.exe` по пути из `wintun.external_engine.executable` (по умолчанию `.bin/tun2socks/tun2socks.exe`, относительный путь резолвится от каталога EXE).

### Где взять бинарники

| Бинарник | Источник | Что положить |
|----------|----------|--------------|
| `wintun.dll` | [https://www.wintun.net](https://www.wintun.net) | Распакуйте архив Wintun и поместите x64-версию в `.bin\wintun\x64\wintun.dll` |
| `tun2socks.exe` | [https://github.com/xjasonlyu/tun2socks](https://github.com/xjasonlyu/tun2socks) (Releases) | Скачайте Windows-amd64 сборку и поместите в `.bin\tun2socks\tun2socks.exe` |
| `WinDivert.dll` + `WinDivert64.sys` | Поставляются в `external\WinDivert\WinDivert-2.2.2-A\x64\` | `build.bat` копирует их автоматически, если они там присутствуют |

## 6. Лицензии внешних бинарников

Внешние компоненты имеют разные лицензии — учитывайте это при распространении поставки:

- **Wintun** (`wintun.dll`): драйвер WireGuard, распространяется под **Prosperity Public License** — это лицензия с ограничением на коммерческое использование (некоммерческое использование бесплатно, для коммерческого требуется отдельное согласование). Файл не входит в репозиторий как продукт — он загружается администратором с [https://www.wintun.net](https://www.wintun.net).
- **tun2socks** (`tun2socks.exe`): проект [xjasonlyu/tun2socks](https://github.com/xjasonlyu/tun2socks), лицензия **MIT** — свободное использование при сохранении копирайта.
- **WinDivert**: распространяется под двойной лицензией **LGPLv3 / GPLv3** (см. `external\WinDivert\WinDivert-2.2.2-A\LICENSE`).

Поскольку все три бинарника опциональны на этапе сборки, вы можете формировать поставку, включающую только те движки, чьи лицензионные условия приемлемы для конкретного развёртывания (например, чисто Wintun-external на MIT-компонентах, или чисто WinDivert).

## 7. Быстрый чек-лист сборки поставки

1. Положить нужные внешние бинарники в `.bin\` (см. §5).
2. Запустить `build.bat` из корня репозитория.
3. Запустить `deploy.bat` (получить `releases\v<VERSION>\`) — либо подготовить `deploy_v3\` для `package.bat`.
4. (ZIP) Запустить `installer\package.bat` → `output\TcpRedirector_<version>.zip`.
5. (EXE) Скомпилировать `installer\setup.iss` в Inno Setup → `output\TcpRedirector_Setup.exe`.
6. Проверить установку по [`docs/УСТАНОВКА.md`](УСТАНОВКА.md).
