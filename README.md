# TcpRedirector

**TcpRedirector** — это система для Windows, которая прозрачно перенаправляет исходящие TCP-соединения выбранных приложений через HTTP-прокси (метод `CONNECT`). Приложение-«жертва» ничего не знает о прокси и продолжает работать так, будто соединяется с адресатом напрямую, — вся подмена происходит на уровне системы. Поддерживается авторизация на прокси по схеме **Basic** (логин/пароль) и **Kerberos/Negotiate** (доменная, без хранения пароля).

Продукт состоит из **фоновой службы Windows** (`TcpRedirectorService.exe`), которая выполняет весь перехват и проксирование, и **графического интерфейса** (`TcpRedirectorGUI.exe`) — WPF-приложения на .NET для настройки правил, параметров прокси и просмотра статистики в реальном времени. Служба и GUI обмениваются данными через локальный IPC-канал и читают/пишут один и тот же файл конфигурации `config.json`, расположенный рядом с исполняемым файлом службы.

После крупного рефакторинга (интеграция Wintun) TcpRedirector поддерживает **два независимых механизма захвата трафика**, переключаемых одним полем в `config.json` без перекомпиляции. Первый — исторический, на базе **WinDivert** (перехват SYN-пакетов в user-mode). Второй — новый, на базе **Wintun** (TUN-адаптер WireGuard + tun2socks-подобный движок), который бывает во встроенном (embedded lwIP) и внешнем (external `tun2socks.exe`) вариантах. Оба режима приводят трафик к одному и тому же локальному TCP-relay, который и устанавливает соединение с вышестоящим прокси.

Служба спроектирована для **постоянной фоновой работы**: она устанавливается как служба Windows с автозапуском, работает под учётной записью `LocalSystem` и не требует интерактивного входа пользователя.

## Ключевые возможности

- **Прозрачное проксирование TCP** для выбранных приложений — целевое ПО не требует настройки прокси.
- **Два режима захвата** (`capture_mode`): `windivert` и `wintun`, переключаются через `config.json`.
- **Три эффективных конфигурации движка**:
  - **WinDivert** — перехват исходящих TCP-SYN через WinDivert;
  - **Wintun + embedded** — встроенный TCP/IP-стек lwIP внутри службы, без внешних процессов;
  - **Wintun + external** — внешний `tun2socks.exe` (проект [xjasonlyu/tun2socks](https://github.com/xjasonlyu/tun2socks)) как контролируемый дочерний процесс.
- **Авторизация на прокси**: Basic (логин + пароль, пароль хранится зашифрованным через DPAPI) и Kerberos/Negotiate (SSPI, доменная авторизация без хранения пароля).
- **Гибкие правила по приложениям** (`apps[]`): сопоставление по имени/пути процесса плюс фильтрация по конкретным портам, диапазонам портов, либо флаг «весь трафик приложения» (`route_all_traffic`).
- **Работа как служба Windows** с автозапуском, под `LocalSystem`, для непрерывной фоновой работы.
- **Графический интерфейс** для настройки и мониторинга (статистика трафика, активные соединения) с **переключателем языка RU/EN** (русский/английский, смена «на лету», выбор сохраняется в `config.json` → `gui.language`).
- **Логирование** в файлы рядом со службой (`logs\`) с настраиваемым уровнем и ротацией.
- **Preflight-проверки**: перед стартом служба проверяет наличие зависимостей **только активного** режима — файлы неактивного режима не мешают запуску.

## Поддерживаемые режимы

TcpRedirector умеет перехватывать трафик тремя способами. Выбор задаётся полями `capture_mode` и (для Wintun) `wintun.engine` в [`config.json`](docs/КОНФИГУРАЦИЯ.md).

| Режим | `capture_mode` | `wintun.engine` | Механизм |
|-------|----------------|-----------------|----------|
| WinDivert | `windivert` | — | Перехват исходящих TCP-SYN драйвером WinDivert, подмена назначения на локальный relay |
| Wintun (встроенный) | `wintun` | `embedded` | TUN-адаптер Wintun + встроенный стек lwIP внутри службы |
| Wintun (внешний) | `wintun` | `external` | TUN-адаптер Wintun + внешний `tun2socks.exe`, форвардящий на локальный SOCKS5-слушатель relay |

### Выбор режима

| Критерий | WinDivert | Wintun (embedded / external) |
|----------|-----------|------------------------------|
| Дружелюбность к AV/EDR | Ниже: WinDivert использует собственный kernel-драйвер (`WinDivert64.sys`), который может помечаться антивирусами и EDR как подозрительный; иногда требуются исключения | Выше: `wintun.dll` — это подписанный Microsoft драйвер WireGuard, широко доверяемый и известный AV/EDR |
| Необходимые бинарники | `WinDivert.dll` + `WinDivert64.sys` рядом с EXE | `.bin\wintun\x64\wintun.dll` (+ `.bin\tun2socks\tun2socks.exe` при `engine=external`) |
| Права | Администратор / `LocalSystem` | Администратор / `LocalSystem` |
| Гранулярность по процессам | Пофайловая (перехват только SYN нужных процессов) | **embedded** — маршрутизирует весь IPv4-TCP через туннель, но фильтрует его **по процессу** внутри движка (те же `apps[]`-правила, что и WinDivert; `wintun.process_filter_enabled`, по умолчанию включено): проксируется трафик только выбранных приложений, а не-целевой (DIRECT) в embedded **отклоняется** (прямой проход мимо прокси не поддерживается — для него используйте WinDivert; чтобы проксировать весь трафик — `process_filter_enabled=false`). **external** — фильтрация по процессу невозможна, проксируется весь трафик |
| Внешние процессы | Нет | `embedded` — нет; `external` — один дочерний процесс `tun2socks.exe` (с авто-рестартом) |
| Когда выбирать | Нужна пофайловая точность; окружение допускает WinDivert | AV/EDR блокирует WinDivert; предпочтителен доверенный драйвер. Для фильтрации по процессу выбирайте **embedded**; **external** — когда фильтрация по процессу не нужна |
| IPv6 | По исходной логике WinDivert | В v1 IPv6-туннель по умолчанию **выключен** (`tunnel_ipv6_cidr` пустой) |

> Подробнее о переключении режимов и их проверках см. [`docs/ПЕРЕКЛЮЧЕНИЕ_РЕЖИМА.md`](docs/ПЕРЕКЛЮЧЕНИЕ_РЕЖИМА.md).

## Требования

- **ОС:** Windows 10 или Windows 11, **только x64**.
- **Права:** установка и работа службы требуют прав администратора; служба работает под `LocalSystem`.
- **Для режима WinDivert:** файлы `WinDivert.dll` и `WinDivert64.sys` рядом с `TcpRedirectorService.exe`.
- **Для режима Wintun:** `.bin\wintun\x64\wintun.dll`; дополнительно `.bin\tun2socks\tun2socks.exe` при `wintun.engine = "external"`.
- **.NET-рантайм для GUI** — не требуется отдельно: GUI собирается как self-contained (рантайм внутри пакета).

## Быстрый старт

1. **Установите** продукт: запустите `TcpRedirector_Setup.exe` (или распакуйте ZIP и запустите `install.bat` от имени администратора). В инсталляторе выберите профиль компонентов: «Полная (оба режима)», «Только WinDivert» или «Только Wintun».
2. **Проверьте службу:** откройте командную строку от администратора и выполните `sc query TcpRedirectorService` — состояние должно быть `RUNNING`.
3. **Откройте GUI** из меню «Пуск» → *TcpRedirector*.
4. **Настройте прокси:** укажите адрес и порт вышестоящего HTTP-прокси, при необходимости включите авторизацию (Basic или Kerberos).
5. **Добавьте правило приложения:** укажите имя/путь целевого процесса и порты (или включите «весь трафик приложения»).
6. **Выберите режим захвата** при необходимости (по умолчанию `wintun` + движок `embedded`). Смена режима — см. [`docs/ПЕРЕКЛЮЧЕНИЕ_РЕЖИМА.md`](docs/ПЕРЕКЛЮЧЕНИЕ_РЕЖИМА.md).
7. **Сохраните настройки** и перезапустите службу (`sc stop TcpRedirectorService` → `sc start TcpRedirectorService` или через GUI).
8. **Проверьте работу:** запустите целевое приложение и убедитесь по логам (`<каталог службы>\logs\`), что соединения проходят через relay и прокси.

## Сборка поставки

Сборка из исходников описана в [`docs/СБОРКА.md`](docs/СБОРКА.md). Обычный конвейер — [`build.bat`](build.bat) → [`deploy.bat`](deploy.bat) → [`installer/package.bat`](installer/package.bat).

Для быстрой сборки «одной командой» есть **easy-режим** — скрипт [`easy_mode_deploy.bat`](easy_mode_deploy.bat) в корне: он выполняет весь конвейер (сборка → упаковка) без участия пользователя, всегда под меткой версии `latest` (файл `VERSION` не изменяется), включает **все доступные движки** (WinDivert, Wintun, tun2socks) и собирает `output\TcpRedirector_latest.zip` (и, при наличии Inno Setup, `TcpRedirector_Setup.exe`). Промежуточная поставка формируется в каталоге `deploy_latest\`. Подробности — в [`docs/СБОРКА.md`](docs/СБОРКА.md) §3.1.
