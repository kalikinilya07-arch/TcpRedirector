# QA-аудит TcpRedirector — 14.07.2026 (динамическая проверка)

**Тип:** независимая ревизия качества с фактической сборкой всех компонентов и
запуском юнит-тестов. В отличие от [`docs/ИЗВЕСТНЫЕ_ПРОБЛЕМЫ.md`](../docs/ИЗВЕСТНЫЕ_ПРОБЛЕМЫ.md)
(статический аудит), здесь **проверены сборки и часть находок исправлена + перетестирована**.

**Окружение проверки:** Windows, VS 2022 (Community, D:), MSVC C++20, .NET SDK 9.0.306,
cmake 4.3.3, Inno Setup. Полноценный рантайм датапата (перехват, прокси, IPC-хендшейк)
**недоступен** — нужны админ-права, драйвер WinDivert64.sys, wintun.dll, tun2socks.exe,
вышестоящий прокси и реальная сеть. Поэтому фиксы делятся на «проверяемые сборкой/тестами»
и «требующие ручной рантайм-проверки на стенде».

## 3. Найденные проблемы (верифицировано по коду)

> Severity: критичная / высокая / средняя / низкая. Помечено, что расходится
> со статическим аудитом (устаревшие/исправленные пункты).

### B1 [Высокая, безопасность] IPC-канал `TcpIpcServer` без аутентификации
- Файлы: `infrastructure/ipc/TcpIpcServer.h`, wired в `ServiceMain.h:318,338`.
- Канал `127.0.0.1:34011` без токена/ACL. Любой локальный процесс/пользователь
  может вызвать `set_config`/`set_rules`/`set_log_level` службы (работает под SYSTEM).
- Ожидаемо: команды управления доступны только Administrators/SYSTEM.
- Фактически: доступ у любого локального процесса.
- (Совпадает с 3.4 статического аудита.)

### B2 [Средняя, корректность] `ConnectionTable`: составной ключ только на записи
- Файл: `infrastructure/relay/ConnectionTable.h`.
- `Add()` дедупит по `(src_port, orig_dest_ip)` (стр. 79), но `Get`/`GetProxyConfigId`/
  `IsTracked`/`SetProcessInfo`/`AddBytes`/`GetInfo` ищут только по `src_port`, а
  `Remove` — только по `src_port` и без проверки `is_tracked`.
- Репро: два одновременных соединения с одинаковым эфемерным `src_port` к разным DST
  → чтение вернёт чужой original-DST → мисроутинг; `Remove` удалит не ту запись.
- (Совпадает с 3.3; исправимо + тестируемо.)

### B3 [Средняя, корректность] Рассинхрон шкалы `log.level` GUI↔служба
- Файлы: `ConfigManager.cpp:180-189` (файл-шкала `0=ERROR,1=WARN,2=INFO,3=DEBUG`),
  `Config.h:62`; GUI пишет доменную шкалу `0=TRACE..4=ERROR`
  (`ProxyConfig.h:138-145`, GUI `LogEntry.LevelDisplay`, `MainWindow.xaml` combo,
  `SettingsViewModel.SaveLogLevelAsync`→`WriteInt("log","level",filter)`).
- Репро: выбрать в GUI «только ошибки» (4) → служба читает 4 → default → INFO;
  выбрать «всё/TRACE» (0) → служба читает 0 → ERROR (наименее подробно). Инверсия.
- Совпадает по значению только для INFO(2). Живой IPC `set_log_level` — по доменной
  шкале (корректно), т.е. persisted и live расходятся. **Новая находка (нет в 3.x).**

### B4 [Высокая, функциональность] Пароль Basic-auth нельзя задать из GUI (сквозной обрыв)
- Файлы: `IpcClient.SetConfigAsync` шлёт `set_password` без значения `password`;
  `IpcHandler.SetConfig` кладёт `plain_password`, но `ConfigManager::SetProxyConfig`
  (`:146-159`) ветку пароля **игнорирует и не сохраняет**; GUI `JsonConfigRepository`
  никогда не пишет `encryptedPassword` (только сохраняет существующий).
- Репро: ввести пароль в GUI → сохранить → пароль нигде не оседает → Basic-auth без пароля.
- Ожидаемо: пароль передаётся службе, та шифрует DPAPI и сохраняет. **Новая находка.**

### B5 [Средняя, надёжность/безопасность] Небезопасный (без кавычек) путь службы при `--install`
- Файл: `main.cpp:88` — `CreateServiceW(..., path, ...)` без кавычек.
- Репро: установка в `C:\Program Files\TcpRedirector\` (дефолт по докам) → ImagePath
  с пробелом без кавычек (unquoted service path). Best-practice/скан безопасности +
  риск запуска `C:\Program.exe`. **Новая находка.**

### B6 [Средняя, GUI] Полные writer'ы конфига перезатирают поля константами и теряют неизвестные
- Файл: `JsonConfigRepository.WriteFull/WriteFullV2` (пересборка объекта заново).
- `stats.updateIntervalMs` всегда пишется `2000` (а читается с дефолтом `1000` в
  `ShellViewModel`), `log.fileEnabled=true`, `proxy.enabled=true` — хардкод; любое
  неизвестное поле (в т.ч. `stats.graphWindowSec`, читаемое `StatsViewModel`) теряется.
- Уточнение к 3.5/3.6 статического аудита: **`process_filter_enabled` и `maxSizeMB=50`
  уже корректно пишутся** (аудит устарел), но остаётся клоббер вышеуказанных полей.

### B7 [Средняя, GUI] Правка существующей строки app-правила не помечает конфиг «грязным»
- Файл: `SettingsViewModel` подписан только на `AppRuleViewModel.ErrorsChanged`, не на
  `PropertyChanged`.
- Репро: изменить Pattern/Ports у существующей строки → индикатор «несохранённые
  изменения» не появляется; при Start/Stop `ReloadFromConfigIfClean` перечитает файл и
  **молча потеряет правки**. **Новая находка.**

### B8 [Низкая] Мёртвый код и реликты
- `CompositionRoot.h` — мёртв (не в vcxproj, не инстанцируется; тянет PipeServer/WinDivert).
- vcxproj `:142` ссылается на несуществующий `domain/ports/IDriverCommunicator.h`.
- Реликты: `build_debug.bat`, `build_refactored.bat` (хардкод-пути), `external/WinDivert.zip` (~405 КБ).
- `ServiceMain.h:379` логирует «PipeServer stopped» (на деле `TcpIpcServer`).
- (Часть 3.7/3.12 статического аудита; корневой `WinDivertCapture.cpp` и пустой
  `build.bat` **уже удалены**.)

### B9 [Низкая] Рассинхрон версий
- `VERSION`=1.0.0 vs дефолты `installer/package.bat`/`setup.iss`=1.1.0. (Совпадает с 3.10.)

### B10..B22 [документируется, не исправляется в этой итерации — глубокий рантайм/высокий риск]
- Embedded-движок: `DecideFlow`/`connect`/`Sleep` под `m_core_lock`; решение один раз на SYN;
  утечка `m_flows`/`m_active_flows` (не убираются в `CloseFlow`/`OnErr`) (3.1, 3.2 + новое).
- WinDivert: кэш DIRECT при `pid==0` может навсегда пустить целевое соединение мимо прокси;
  `windivert_debug.log`/stdout пишутся всегда, вне уровня, вне retention.
- Relay: `WSACleanup()` при живых bridge-потоках; bind `INADDR_ANY:34010`.
- `ChildProcessSupervisor`: гонка двойного закрытия HANDLE на остановке.
- DPAPI per-user vs служба-SYSTEM (обрыв расшифровки при кросс-аккаунтном сценарии).
- Рассинхрон резолверов пути службы (`AppPaths` vs `ServiceController`).
- Прочие мелочи GUI/потоки (см. инвентаризацию в отчёте).
