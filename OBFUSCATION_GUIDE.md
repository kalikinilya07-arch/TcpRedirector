# Руководство по обфускации для снижения ложных срабатываний антивируса

## ⚠️ Важное предупреждение
Обфускация требует **пересборки приложения** (изменения бинарных файлов). Если вы не можете менять приложение вообще (ни пересборку, ни изменение бинарников), то обфускация невозможна. В этом случае используйте только рекомендации по исключениям в антивирусе (см. AV_ANALYSIS.md и KASPERSKY_EXCLUSIONS.md).

Если вы можете пересобрать приложение (но не менять исходный код логики), то эта инструкция для вас.

## 🔧 Обфускация .NET части (TcpRedirectorGUI)

### Инструменты:
1. **ConfuserEx** (бесплатный, открытый исходный код)
   - Ссылка: https://github.com/mkaring/ConfuserEx
   - Особенности: защита строк, управление потоком управления, ссылки-ссылки, шифрование ресурсов
   - Как использовать: добавить в пост-сборку события проекта или использовать CLI

2. **Dotfuscator Community Edition** (бесплатная версия от PreEmptive)
   - Ссылка: https://www.preemptive.com/products/dotfuscator/ce
   - Особенности: переименование, удалениеunused кода, управление потоком управления
   - Интеграция: Visual Studio extension

3. **ArmDot** (бесплатный для открытых проектов, коммерческий для закрытых)
   - Ссылка: https://github.com/snyk/armdot
   - Особенности: виртуализация кода, защита строк, смешивание кода

### Настройки для TcpRedirectorGUI:
- Исключить из обфускации: 
  - Входные точки (Main, методы WPF команд, сервисы)
  - Интерфейсы и публичные методы, используемые через рефлексию (например, IConfigRepository, ITcpRedirectorService)
  - Атрибуты и свойства, привязанные в XAML (Binding, Commands)
- Включить:
  - Переименование символов (имена классов, методов, полей)
  - Управление потоком управления (Control Flow Obfuscation)
  - Шифрование строковых literals
  - Сжатие и обфускация ресурсов

### Пример пост-сборки для ConfuserEx (в .csproj):
```xml
<Target Name="AfterBuild">
  <Exec Command="\"$(SolutionDir)\tools\Confuser.Cli.exe\" crashrepair -p \"$(ProjectDir)confuser.xml\" \"$(TargetPath)\""/>
</Target>
```

## 🔧 Обфускация C++ части (TcpRedirectorService)

### Инструменты:
1. **Obfuscator-LLVM** (open-source)
   - Ссылка: https://obfuscator-llvm.org/
   - Требует: сборка LLVM с патчами, пересборка проекта с использованием модифицированного Clang
   - Техники: подмена управления потоком, подмена арифметики, подмена логических операций

2. **VMProtect Ultimate** (коммерческий)
   - Ссылка: https://vmpsoft.com/
   - Особенности: виртуализация кода, генерация уникальных виртуальных машин для каждого экземпляра
   - Поддерживает: Windows PE файлы (EXE, DLL, SYS)

3. **Themida** (коммерческий)
   - Ссылка: https://www.oreans.com/themida.php
   - Особенности: многоуровневая защита, виртуализация, защита от отладки и дизассемблирования

4. **Защита компилятора MSVC** (ограниченная, но бесплатная)
   - Опции: `/d2guard4` (включает проверки переполнения буфера), `/GS` (проверка переполнения стека)
   - Не является полной обфускацией, но может снизить некоторые эвристические срабатывания

### Настройки для TcpRedirectorService:
- **Критически важно**: не обфусцировать:
  - Точку входа (`main`, `ServiceMain`)
  - Функции обратного вызова службы (`ServiceControlHandlerEx`)
  - Экспортированные функции (если есть)
  - Функции, используемые через `GetProcAddress` (если применяется динамическая загрузка DLL)
  - Функции, связанные с WinDivert (если они вызываются по имени из драйвера или через динамическую загрузку)
  - Функции работы с named pipes (если имена жестко закодированы и используются в `CreateNamedPipeW`/`ConnectNamedPipe`)

- Можно обфусцировать:
  - Внутренние функции обработки пакетов
  - Функции работы с конфигурацией
  - Вспомогательные строковые функции
  - Логирование

### Пример использования Obfuscator-LLVM (CMake):
```cmake
# В CMakeLists.txt
set(CMAKE_CXX_COMPILER "clang")
set(CMAKE_CXX_FLAGS "${CMAKE_CXX_FLAGS} -mllvm -fla -mllvm -bcf -mllvm -sobf")
```

## 📝 Общие рекомендации по обфускации

1. **Тестирование после обфускации**:
   - Пройти полное регрессионное тестирование GUI и службы
   - Проверить работу named pipe IPC между GUI и сервисом
   - Проверить захват и перенаправление трафика через WinDivert
   - Убедиться, что служба устанавливается, запускается и останавливается корректно

2. **Подпись кода** (обязательна после обфускации):
   - Используйте сертификат кодовой подписи (EV сертификат предпочтителен)
   - Подписывайте все бинарники: .exe, .dll, .sys (WinDivert64.sys должен оставаться неподписанным или подписанным его оригинальным разработчиком - обычно он уже подписан)
   - Подпись снижает вероятность эвристических срабатываний

3. **Комбинированный подход**:
   - Сначала примените обфускацию
   - Затем подпишите код
   - Затем настройте исключения в антивирусе как последний рубеж защиты

4. **Риски обфускации**:
   - Ложные срабатывания heuristic антивируса на саму обфускацию (некоторые AV помечают упакованные/обфусцированные файлы как вредоносные)
   - Возможные сбои в работе приложения из-за обфускации критических путей
   - Увеличение размера бинарника и потенциальное снижение производительности

5. **Альтернатива**: если обфускация нежелательна или невозможна, сосредоточьтесь на:
   - Получении сертификата кодовой подписи
   - Отправке образцов в антивирусные компании для добавления в белый список
   - Детальной документации легитимности применения (сетевой прокси с аутентификацией)

## 📋 Чек-лист перед релизом обфусцированной версии

- [ ] Собрано приложение с обфускацией (оба модуля)
- [ ] Проверено, что точки входа и критические IPC-механизмы не обфусцированы
- [ ] Подписано все исполняемое ПО (кроме сторонних драйверов, если они уже подписаны)
- [ ] Пройдено функциональное тестирование (GUI ↔ служба ↔ сетевой трафик)
- [ ] Запущено в тестовой среде с активным Kaspersky и Windows Defender
- [ ] Отсутствуют ложные срабатывания в журналах антивируса
- [ ] Подготовлен отчет о ложных срабатываниях для отправки в вендоров AV (если они все еще возникают)

---

*Примечание: Обфускация не гарантирует отсутствия ложных срабатываний, но значительно снижает вероятность эвристических срабатываний. Комбинированный подход (подпись + исключения + обфускация) дает наилучший результат.*
